# 开源复用对照

本工作区的流程框架参考了两个开源项目，按中国大陆求职场景做了改造。
本文说明「参考了什么、改了什么」，具体条款以对方仓库为准（我们只对照公开可见的 README 层面，不逐条搬运其内容）：

- [career-ops-zh](https://github.com/TongyiDai/career-ops-zh)
- [JobOK](https://github.com/GresonKwan/JobOK)

## 参考的部分

| 主题 | 参考点 | 来源 |
|---|---|---|
| 流程骨架 | 画像 → 岗位 → 评估 → 材料 → 投递 → 复盘 的漏斗形态 | 两者均有类似阶段划分 |
| 先筛再投 | 红线一票否决 + 加权评分的思路 | JobOK 的评分思路 |
| 本地优先 | 数据留在本机、不上云 | career-ops-zh 的本地工作区理念 |

## 本仓库的改造（差异点）

1. **证据链纪律产品化**：needs_proof 标记贯穿事实库 → 草稿 → 可投递版本，
   脚本层保证「无来源内容进不了正文」，而不只靠提示词约束。
2. **三档技能制**（expert / practiced / learned）：learned 永不写成项目经验，
   评分脚本与简历草稿都执行这条规则。
3. **规则单文件化**：红线与七维评分全部在 `config/scoring.yml`，
   脚本与 AI 提示词引用同一份规则，不存在第二套口径。
4. **零依赖工具链**：Python 标准库 + 原生 JS，无 node_modules、无数据库、无框架。
5. **模板/私人分离**：`private/` 之外全部是空白模板与可复用流程，可直接建仓开源而真实资料不出本机。
6. **JD 由人工采集**：不绕过登录/验证码/反爬，inbox 只收人工复制的 JSON。
7. **tracker 幂等更新**：重跑评估不覆盖人工推进状态（已投递、简历版本号）。

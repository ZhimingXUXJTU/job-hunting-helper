# 工作指令 02 · 评估 JD（先筛再投）

> 你的任务：对一份 JD 做红线判定与七维评分。
> 规则以 `config/scoring.yml` 为唯一标准，你不另行发明规则。

## 输入

- JD 文件：`jobs/inbox/<file>.json`（用户指明，或取 inbox 里最新的）
- 规则：`config/scoring.yml`
- 事实库：`candidate/private/facts.yml`

## 流程

1. **先跑脚本**：`python -X utf8 tools/run_workflow.py --workspace . --jd jobs/inbox/<file>.json`
   —— 得到规则版的红线判定、七维分数与产物草稿。
2. **再做模型复核**（你比脚本多做的事）：
   - 读 JD 全文与事实库，对每个维度给出你的独立判断与依据，与脚本分不一致时**两份都写出来**，不悄悄改分；
   - 识别脚本看不到的信号：职责层级、团队氛围、业务前景、JD 里的隐含加班暗示；
   - 公司风险：用 JD 文本与录入时的 `risk_notes` 判断，不联网搜索（除非用户要求）。
3. **缺信息不猜**：薪资、城市、发布时间缺失时保留人工复核标记。

## 输出

在 `reports/private/<job_id>.md` 的脚本报告后追加一节：

```markdown
## 模型复核（AI 独立判断）

- 与脚本评分的差异及理由：……
- JD 里的额外信号：……
- 建议：推进 / 复核 / 观察 / 放弃，以及一句话理由
```

## 纪律

- 打分依据必须引用 JD 原文或事实库字段，说不出依据的分数不要给。
- 匹配分衡量的是信号强度，不是录用概率——报告里不要出现「录取概率」之类表述。
- 红线命中即淘汰，不因为「技能很匹配」而通融。
- 薪资不是红线：按综合年包（月薪×薪数）进评分，低于事实库底线只减分；JD 没写薪资标人工复核，不猜。

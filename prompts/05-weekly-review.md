# 工作指令 05 · 每周复盘

> 你的任务：每周一次，盘点投递漏斗与事实库健康度，输出下周计划。
> 只统计 tracker 里的事实，不做归因发明。

## 输入

- `applications/private/tracker.csv`
- `reports/private/` 下本周评估记录（evaluated_at 在本周内）
- `candidate/private/facts.yml`（needs_proof 存量）

## 输出

写 `reports/private/weekly-<YYYY-Www>.md`：

```markdown
# 每周复盘 · YYYY 第 WW 周

## 漏斗（只数数，不解释因果）

- 新收 JD：N 份 → 评估 N 份 → 推进 N / 复核 N / 观察 N / 放弃 N / 红线 N
- 投递：本周 N 份（累计 N）→ 已回复 N → 面试 N → 拒绝 N → 进行中 N
- 回复率、面试转化率：如实相除，样本小于 10 时标注「样本太小，仅供参考」

## 事实库健康度

- needs_proof 存量：N 条（比上周 +N/-N）
- 本周补齐的证据：……
- 面试中被问倒、事实库答不上的问题：……（下周优先补）

## 规则是否需要调整（只提观察，不改文件）

- 红线误杀/漏放的案例：……
- 分数与实际回复不一致的岗位：列出 JD 与得分，供人工判断 scoring.yml 是否要改

## 下周计划

- 收岗位目标：N 份；重点推进岗位：……
- 待补证据：……
```

## 纪律

- 所有数字来自 tracker 与评估记录，不凭记忆。
- 「分数高但没回复」只呈现现象，不发明因果解释（简历版本、市场、岗位真假都可能）。
- scoring.yml 的修改建议只写在复盘里，改不改由人决定。
